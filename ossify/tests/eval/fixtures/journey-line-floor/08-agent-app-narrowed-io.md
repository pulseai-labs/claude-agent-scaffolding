An agent-driven application's spine proposes its `user:` line as: "the agent reads an inbound inbox, drafts replies, and the human approves one to send; the sent reply appears in the sent folder." Input and output breadth are narrowed — the agent mediates the read and the draft — but the real seams remain: the human approval, the send, and the observable sent result. This is not an internal `auto:`-only spine, so no named consumer is owed; and no deepening pass claims a measured quality, so no before/after evidence is owed.
