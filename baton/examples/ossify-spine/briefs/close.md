# Close

Run `/ossify:close <work item> --pr --verdict <Verdict file from your message>` on Claude Code, `skill://close <work item> --pr --verdict <Verdict file from your message>` on OMP. The verdict is the verify stage's: close runs Layers 1 and 2 itself and applies the verdict's `rule`, `lenses` and `mutation`, so a halting verdict is a red gate like any other. On any red gate, whichever layer halts, write ossify's `OSSIFY CORRECTION CONTINUATION v1` packet (`work-item/references/correction-continuation.md` §2) to the correction packet file and end: `handoff_path` and `work_item_id`; `expected_branch` the branch; `expected_head_sha` the base SHA (implementers never commit); `expected_tree_oid` from `git -C <worktree> write-tree` at the gate; `failures` every source-tagged finding. The dispatcher routes the correction. Any other halt — a merge conflict, an identity check, a verdict that is not this tree's (`verdict identity … does not match`, `verdict is for …`) or not in the verdict shape, the remote leg — is a stop. Never pick a recovery option.
